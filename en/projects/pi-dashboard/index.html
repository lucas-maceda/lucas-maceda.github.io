Pi Dashboard

A touch dashboard for a Raspberry Pi: clock, weather, pomodoro, email, calendar, tasks and music on a 7-inch screen.

This is the first open source project I’ve published as such, and it makes me really happy that it’s something genuinely useful, cheap and easy to maintain. What has surprised me most is how much I use it day to day, because sometimes we build ideas that feel super important and necessary for our workflows and end up not using them, because of how hard they are to get running day to day or to maintain over time.

Why

The plan was simple: make use of an old 7-inch screen I bought many years ago. I originally used it on my desktop PC to show temperatures with Rainmeter and to keep a small Spotify window open while I did other things. I also bought the Raspberry Pi 3B when it came out, in 2016, to build a retro gaming machine for the living room. Later on I used it to control a 3D printer and get access to a webcam. It was the easiest way to keep an eye on it and make sure it wasn’t setting my parents’ house on fire.

At first I wanted to set up a mini server in my flat, but after seeing the technical limitations of this board, I decided to combine it with the screen to have a small command centre for everything I like to check regularly: the time, the weather, my Google Tasks notes, calendar events… I also added features I used to need my phone for, like a pomodoro timer or seeing whether I’d got new emails.

What I built

I set out to keep the code as simple and easy to update as possible, always bearing in mind that I didn’t want it to depend on my computer being around. Since the screen is a touchscreen, I wanted it to be as autonomous as possible, but also to be able to connect to it locally from any device to change things. It could be swapped for a tablet, but the server would have to be modified to run on another device. Right now I can have the Raspberry Pi in my bedroom and the tablet showing the same panel in the living room.

Tech stack

The Raspberry calls the shots here. With 1 GB of RAM there isn’t much room to play with, so I chose every piece thinking about keeping it light and about still understanding what I did a couple of years from now. The idea is simple: a single Python server holds the state and fetches the data, and the web app only takes care of drawing it. That’s why it doesn’t matter which device I connect from, because they all see the same thing instantly.

  • Server: Python with FastAPI and Uvicorn. Requests to external APIs go through HTTPX, and I use Pillow to get the average colour of the Spotify album art, which is a silly little thing but brings the card to life.
  • Interface: Svelte 5 and Vite, because it compiles down to very little JavaScript and you notice that on a board this old. To place and resize the widgets on the grid I use Gridstack.
  • Real time: WebSockets between the server and the screens, so the pomodoro runs the same on the Raspberry as on the tablet.
  • Data: the Gmail, Google Calendar, Google Tasks and Spotify APIs with OAuth, and Open-Meteo for the weather. There’s no database, everything is saved in JSON files on the board itself.
  • System: Raspberry Pi OS Lite with no desktop, running Chromium in kiosk mode inside Cage, a minimal Wayland compositor that only knows how to show one app full screen. Two systemd services make sure everything starts on its own as soon as you plug it in.
  • Tests: pytest on the server and Vitest on the web app, so I can change things without being afraid of breaking the panel I use every day.

Open source

The open source community has given me a lot throughout my journey as a developer. If it weren’t for sites like SourceForge or posts on all sorts of forums, I couldn’t have taken inspiration from, or in many cases copied, other projects in order to learn. I believe sharing projects is how we reach new ideas, and that this mindset is making a comeback with the rise of AI-assisted programming. Ideas, always backed by knowledge of infrastructure and design patterns, put a finished product within reach of far more people and let us move forward as a community, more than if these advances were kept private.

So if you’ve got a Raspberry gathering dust in a drawer, like mine was, the code and the guide to build your own are on GitHub. Take it, break it and make it yours.
